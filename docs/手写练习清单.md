## 练习 1:RRF 融合(最简单,先建立信心)

**目标**:实现 `rrf_fuse`,把两个"按相关度降序"的检索结果合并成一个排序。

**为什么需要它**:向量检索和 BM25 的分数域不同(余弦相似度 vs BM25 分数),
直接相加没有意义;RRF 不看分数绝对值,只看"排名",用排名倒数统一量纲。

**核心公式**(记在心里):
```
score(chunk) = Σ_retriever 1 / (k + rank)     # k 默认 60,rank 从 1 开始
```

**提示**:遍历两个列表,`enumerate(..., start=1)` 拿排名;字典累加分数;
按分数降序排序,截断 top_k;用 `dataclasses.replace` 复制 chunk 并写入融合分。

**项目对照**:`src/retriever/rrf.py`(全文约 35 行,核心 10 行)

**验证**:
```bash
cd /mnt/e/reasonix/medidoc
conda activate docpilot
pytest tests/test_retriever.py::test_rrf_fuses_rankings -v
```

**口头验收**:能解释"为什么 rank 1+2 的分数 > rank 1+3"(1/61+1/62 > 1/61+1/63)。

## 练习 2:手写 BM25(面试高频,权重最高)

**目标**:不用第三方库,实现 BM25 索引(`build` + `search`)。

**上下文**:BM25 是关键词检索的工业标准,在项目里服务于"稀疏通道"——
中文问题翻译成英文后,用 BM25 找字面命中的英文段落(向量检索找语义相关的)。

**核心公式**:
```
score = Σ_token idf · f·(k1+1) / (f + k1·(1 − b + b·dl/avgdl))
idf = ln((N − df + 0.5) / (df + 0.5) + 1)      # k1=1.5, b=0.75
```
其中 f=词在文档中的频次,df=包含该词的文档数,dl=文档长度,avgdl=平均长度。

**提示**:`build` 时对每篇文档分词(Counter 统计频次),统计全局 df,算 idf;
`search` 时对查询分词,逐文档累加分数;分词规则:`re.findall(r"[a-z0-9]+|[\u4e00-\u9fff]", text.lower())`
(英文单词 + 中文单字)。**注意空语料的除零保护**——这是当初踩过的坑。

**项目对照**:`src/ingest/store.py` 的 `BM25Index` 类(约 60 行,无第三方依赖)

**验证**:
```bash
pytest tests/test_store.py::test_bm25_search -v
```

**口头验收**:能推导为什么"出现次数多但到处都有的词"(如 the)分数低。

## 练习 3:ReAct 循环(Agent 核心,面试必问)

**目标**:实现一个最小的 ReAct 循环:模型交替输出 Thought → Action →
Observation,直到 Final Answer。

**上下文**:这是阶段四的核心,让 LLM 能"先查资料再回答"——多步检索、
修正查询、综合多篇证据,处理 direct_rag 搞不定的复杂问题。

**核心结构**(伪代码,把它写出来):
```
messages = [system, 历史, user问题]
while True:
    if 步数超限: 停止(护栏)
    text = chat(messages)
    if 包含 "Final Answer": 提取答案,结束
    解析 "Action: 工具名" + "Action Input: {JSON}"
    if 解析失败: 提示模型按格式输出,continue
    if 连续重复同一动作: 停止(防死循环)
    执行工具(Pydantic 校验 + 超时 + 重试)
    messages.append(Observation: 工具结果)
    步数 += 1
```

**提示**:正则提取 Action/JSON;工具参数用 Pydantic `model_validate` 校验;
执行放 `ThreadPoolExecutor` 实现超时;护栏(步数/重复/费用)每个循环检查。

**项目对照**:`src/agent/loop.py`(约 180 行)+ `src/agent/tools.py`(工具定义)

**验证**:
```bash
pytest tests/test_agent.py -v     # 覆盖:直接回答/工具调用/重复停止/步数上限/非法参数
```

**口头验收**:能画出循环流程图,并说明三个护栏分别防什么。

## 练习 4:双通道检索编排(理解整条检索链路)

**目标**:编排"稠密 + 稀疏 → 融合 → 精排 → 取上下文"的完整链路。

**上下文**:一次问答的检索流程——
1. 中文问题向量化 → Qdrant 找语义相近(top-30);
2. 中文翻译成英文 + 术语扩展 → BM25 找字面命中(top-30);
3. RRF 融合取 top-30 → SiliconFlow rerank 精排取 top-20;
4. 取前 6 条作为生成上下文。

**提示**:写一个 `retrieve(query_vector, query_text, translated_query)` 方法,
依次调用各组件,用 `time.perf_counter()` 记录每段耗时(观测日志的 trace 字段来源),
rerank 结果用 `r.index` 映射回候选列表。

**项目对照**:`src/retriever/pipeline.py`(约 100 行)

**验证**:
```bash
pytest tests/test_retriever.py -v
```

**口头验收**:能说清"为什么 rerank 只对 top-30 而不是全部 1868 个 chunk 做"。

## 练习 5:评估集构建(反向生成,展示工程化意识)

**目标**:实现"抽样段落 → LLM 反向生成问答对 → 自动核验 → 划分 dev/test"。

**上下文**:RAG 项目最难的是"怎么知道做得好不好"。反向生成把"段落本身"当
标准答案(段落 → 让 LLM 基于它提问 → 问题+段落就是一条带 gold 的训练/测试样本),
零人工标注。项目里还做了:按文档划分防泄漏、≥20% 无答案问题测拒答。

**提示**:写 `build_dataset`:
- 从 SQLite 抽样 ready 文档的段落(过滤过短文本);
- 调 DeepSeek 生成 `{question, answer}`(JSON 解析,容忍 markdown 围栏);
- 抽样 20% 用 LLM-judge 打"忠实度"分,低于阈值丢弃;
- **按文档划分 dev/test**(同一文档的样本不能同时出现在两边);
- 追加无答案问题。

**项目对照**:`src/evaluator/dataset.py`(约 150 行)

**验证**:
```bash
pytest tests/test_evaluator.py -v
```

**口头验收**:能解释"为什么反向生成的答案天然忠实"(答案由段落生成,标准答案即段落)。

- 每天 1 个练习,按 1→2→3→4→5 顺序(难度递增);
